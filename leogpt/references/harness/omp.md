# Harness: OMP

You are in OMP when your tools include `task` (with a required `solutionSpace` field), `eval`, and `todo`. Read this skill's files with `read skill://leogpt/<path>`. Give subagents absolute paths, as the brief requires.

## 1. Spawn a subagent

Tool `task`, batch shape: `{ context, tasks[] }`. One subagent per item. Each item takes `agent`, `task` (the brief), `solutionSpace`, and optionally `name`, `outputSchema`, `schemaMode`, and `isolated`.

- `context` is required and must not be empty. Put the text every item shares there, for example the mental model. Each item's `task` carries the rest of its brief.
- `solutionSpace` is required: one line on how open the child's problem is (`one fix: rename, names given`, `cause open, no repro`).
- `agent` is the role's agent, per section 2. Omit it only when the role has no model: the bundled `task` agent then inherits the lead's model.
- Read-only is not enforced: the brief's scope line carries it. The one exception is plan mode, where every child is read-only. Run no implementer there.
- Parallel: put every independent subagent in the same `tasks[]`. With `async.enabled`, the call returns at once and each result is injected into the conversation when it finishes. Otherwise the call blocks until all finish. Never poll: call `wait` only when you are blocked.
- Continue a child that already returned with `write agent://<id>`. Its context stays intact. Its full output is at `agent://<id>` and its transcript at `history://<id>`.
- Children do not inherit the conversation. The brief is their only context.

## 2. Pick the model

The `task` tool has no `model` parameter. The model is fixed by the agent, so leogpt keeps one agent per role in `~/.omp/agent/agents/` (section 6). Set `agent` to:

| Role | Agent |
|---|---|
| explorer (lookup and report) | `leogpt-explorer` |
| designer | `leogpt-designer` |
| implementer | `leogpt-implementer` |
| verifier | `leogpt-verifier` |
| reviewer | `leogpt-reviewer` |
| judge | `leogpt-judge` |
| arena candidate `n` | `leogpt-arena-design-<n>` or `leogpt-arena-implementation-<n>` |

- A role that resolves to `none` has no agent file: omit `agent`.
- The distinct-models rule of `references/config.md#models` picks among existing agents: take the agent of another role of the same tier whose model differs (for example a `leogpt-arena-design-<n>` for the design challenger). With none, keep the role's own agent and say so in one line.
- If `task` answers `Unknown agent "leogpt-…"`, the agent files are missing or stale. Fall back to the bundled `task` agent and say so in one line. Rerun setup afterwards.

## 3. List available models

Run `omp models` in the shell. It lists every model of the authenticated providers as `provider/model`. `omp models find <substring>` narrows it, and `omp models --json` gives machine-readable output. A value in `models.omp` is a selector `provider/model`, with an optional thinking suffix such as `:high`.

## 4. Ask multiple-choice questions

Tool `ask`: one call with several `questions`. Each has an `id`, a `question`, 2 to 5 `options` (each with a short `label` and an optional `description`), `multi` when choices combine, and `recommended` (a 0-based index; the tool appends "(Recommended)"). Never add an "Other" option: the UI adds it.

## 5. Isolate an arena candidate

There is no isolation the skill relies on. `isolated: true` exists only when `task.isolation.enabled` is set, and its result is a patch or a branch depending on the user's settings. Before spawning each candidate, create a worktree yourself: `git worktree add ../<repo>-arena-<n> -b arena/<slug>-<n>`. Pass its absolute path in the brief and scope the candidate's writes to it. Remove the worktrees with `git worktree remove` after the graft.

## 6. Native config written by setup

Setup writes one agent file per role in `~/.omp/agent/agents/`. It never writes to a project's `.omp/agents/`, which would override the user-level file. Files:

- `leogpt-explorer`, `leogpt-designer`, `leogpt-implementer`, `leogpt-verifier`, `leogpt-reviewer`, `leogpt-judge`;
- `leogpt-arena-design-<n>` and `leogpt-arena-implementation-<n>`, one per entry of the matching `arena.*` list.

Resolve each role's model per `references/config.md#models` (role key, else tier key). Skip a role that resolves to `none`. Template, with the resolved selector:

```markdown
---
name: leogpt-<role>
description: leogpt <role> subagent. Spawned by the leogpt skill only.
model: <provider/model>
---

Do exactly what the brief asks, within its Scope section.
Generated by /leogpt setup. Change the model in ~/.agents/config/leogpt.md, not here.
```

There is no `tools` line: the child gets the default tool set, and the brief's scope line restricts it. Show the files before writing. Delete any `leogpt-*` agent file that no longer matches a role.

Configuration stays the source of truth. Whenever `models.omp` changes, rewrite the affected agent files in the same step. A new file works at once: OMP rediscovers agents on every spawn.

## 7. Limits

- `task.agentModelOverrides[<agent>]` in the user's `config.yml` outranks the agent's `model`. If a `leogpt-*` agent runs on another model than configuration says, look there.
- Only the lead spawns. The agent files declare no `spawns`, and `task.maxRecursionDepth` defaults to 2.
- `task.maxConcurrency` bounds the fan-out: extra subagents queue.
- `task.disabledAgents` can disable a `leogpt-*` agent. It then fails as unknown: fall back per section 2.

## 8. Additional capabilities

Apply `references/capabilities.md`. Delegation, continuation, parallelism, model profiles, choice UI, and manual isolation follow sections 1–5. Inspect retrieval and wake-up tools; state and memory use file fallbacks.
